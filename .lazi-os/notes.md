# cntknw
Purpose: CNTKNW is a local-first offline reading, annotation and study environment that treats PDFs/artworks as objects in a personal knowledge museum. It serves deep reading by binding one canonical journal, annotations, drawings and study views to exact source locations without cloud dependence.
Current state: The verified vertical slice is complete through Phase 3 and WORKSPACE UX-1: PDF import/exact resume, one source-bound journal, highlights/region annotations with canonical rotation-aware geometry, freehand vector drawing blocks, Zen split/focus workspace, whiteboard projection and local Pomodoro; IndexedDB/Dexie persistence, mandatory optimistic concurrency and offline assets are covered by the current test suites.
In progress: Phase 4 has not started; connections/backlinks, graph/map and argument maps remain future work after the completed Phase 3/UX-1 baseline. Known gaps include cross-source search/dictionary, read-aloud/TTS/OCR, multi-device sync and partial soft-delete; see `docs/CNTKNW_Current_Implementation_Status.md`.
Next up: 1) Phase 4A connections/backlinks; 2) Phase 4B graph/map; 3) Phase 4C argument maps, with each phase preserving the existing journal/persistence/concurrency contracts.
Gotchas: The journal is one canonical store per source and the whiteboard is only a projection; do not create duplicate content stores. Every revisioned mutation requires a `ConcurrencyGuard`; annotation geometry is asset-bound and canonical; only Chromium currently has automated E2E evidence.
Do not touch: The checksummed/sealed canonical v0.2 documentation package in `docs/` in place, mandatory concurrency guards, schema/migration contracts, or canonical journal/annotation geometry semantics without an ADR-backed migration.
